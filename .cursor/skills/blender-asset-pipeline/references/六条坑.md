## 坑一：细长件的"长轴 / 宽轴 / 薄轴"

任何细长或不对称的东西（剑刃、刀、瓶、木板、骨头、螺丝刀头、枪管），三个轴的**含义不同**：

- **长轴** = 长度（剑刃 78 cm）
- **宽轴** = 宽面（剑刃 4.5 cm，是"能看出是把剑"的那个面）
- **薄轴** = 截面厚度（剑刃 0.8 cm，也就是刃口方向）

**永远让宽轴朝向英雄镜头的相机。** 从薄轴看过去的剑，渲染出来就是一根细棍。

| 物体 | 局部 X | 局部 Y | 局部 Z |
|---|---|---|---|
| 剑刃 | 薄 0.8 cm | 宽 4.5 cm | 长 78 cm（竖直） |
| 刀刃 | 薄 | 宽 | 长（水平） |
| 木板 | 薄 | 宽 | 长 |
| 瓶子 | 对称（半径） | 对称（半径） | 长（高度） |

建完记得**旋转物体**让宽面朝向相机：相机在 -Y 方向时，把刀刃绕 Z 转 90°，局部 Y 宽轴就朝向世界 X，宽面可见。

**checklist**：动手前在注释里写 `(长, 宽, 薄) = (局部?, 局部?, 局部?)`。

## 坑二：拼件接缝 —— 可视拼接与真实连接是两回事（★ 全场最高价值）

多部件拼装（剑 = 刃 + 护手 + 柄 + 柄头；角色 = 身体 + 装备）时，**面贴面**即使数值上接触，渲染也会有可见的缝；
不同形状之间（圆柱柄插进方块护手）更明显。

展示模型的做法是**隐藏交叠**：让两件在不可见处互相压进去一点，缝就没了。

### ① 展示层：隐藏交叠 + 按 spec 复核

- 拼接可以在**不改变可见轮廓、不捅穿薄壳**的前提下选择隐藏交叠（把交叠埋在较大件内部或不可见面之间）；
- **交叠量由本项目的 spec 明文规定**（接口表逐条写自己的值）；**没有通用倍数、百分比或下限**。
  spec 没写就回去问规格，**别自己发明一个数**；
- 装配后按 spec 复核三件事：交叠量、浮空、真互穿。

> ★ 曾有多版"拼件互相插入 5–15 mm"或"1–2× 接口特征尺寸"的通用通则，**已全部撤回**。
> 任何"通用倍数"都是错的：交叠量取决于件的大小、材质、渲染精度和工艺，只能由 spec 定。

### ② 真实连接不由可视脚本裁定

一件东西**能不能承载、抗扭、抗弯、装不装得上**，由**设计配合（配合与公差）、适用标准、承载工况、
制造工艺（壁厚 / 拔模 / 打印方向）与运动间隙**共同规定 —— 这些都是要人给的设计输入。

**几何脚本只回答"叠没叠、浮没浮、穿没穿"，不能给结构强度结论。**
`volume_mm3` / `pair_count` / `axis_overlap_mm` 都不是强度或连接合格证。

### ③ 逐轴 AABB 重叠有口径坑

`axis_overlap_mm` 是**逐轴 AABB 重叠**，不是三角级。

- **只有"接口法线与某根世界轴一致、且轴对齐盒这个近似对这种几何适用"时**，逐轴 AABB 才能当粗筛；
  此时读**接口法线那一根轴**的值 —— 不是取最大、也不是求和；
- **旋转 / 斜置接口不能这么读**：接口法线不与世界轴对齐时，"挑一根世界轴"量到的是**盒子的重叠**，
  不是接口处的深度。必须**沿真实接口的局部坐标**去量测真实表面，或改用三角级证据；
- 读法示例（**只演示怎么读 AABB，不构成任何深度标准**）：
  Ø6 轴入毂若接口轴与 z 一致、回执给 `{x:6, y:6, z:6}`，z 的 6 是盒级重叠；
  3 mm 薄板搭接给 `{x:180, y:200, z:1.5}` —— x/y 那 180/200 是**板本身有多大**，跟交叠无关。
  **只看单个数或取最大值必然得出错误结论**；
- **AABB 相交 ≠ 真的有交叠**：全内含的 10 mm 浮块同样给 `overlap_bbox=true`、三轴各 10 mm。
  所以交叠复核**必须与浮空检查并跑**；
- 要**真三角级**穿透证据用三角求交的 `volume_mm3` / `pair_count`。
  注意：**共面且互相覆盖的面不报** —— 共面贴合要看接触检测。

### ④ 圆润件开平滑着色

`bpy.data.meshes[].polygons[].use_smooth = True`（headless 稳）或 GUI 里 `bpy.ops.object.shade_smooth()`。
平面着色的圆柱能看出每一段棱面；方块类硬表面保持平面着色。

> Blender 5.x 已移除 `Mesh.use_auto_smooth`，用修改器式平滑（Weighted Normal / Smooth by Angle）或逐面标记。

### ⑤ 想要真正无缝

把同材质的件 Boolean Union 成一个网格 —— **但仅限材质相同**。

## 坑三：收尖不能只靠缩放

把顶部顶点缩到接近 0 会得到"凿子一样的平头"。正确做法是**把顶点压到中线再合并**：

```python
import bpy, bmesh

obj = bpy.data.objects['GEO-blade']
bpy.context.view_layer.objects.active = obj

bm = bmesh.new()
bm.from_mesh(obj.data)
bm.verts.ensure_lookup_table()

max_z = max(v.co.z for v in bm.verts)
top_verts = [v for v in bm.verts if abs(v.co.z - max_z) < 0.001]
for v in top_verts:
    v.co.x = 0.0
    v.co.y = 0.0

# 少了这步就是退化拓扑的"假尖"
bmesh.ops.remove_doubles(bm, verts=top_verts, dist=0.001)

bm.to_mesh(obj.data)
bm.free()
obj.data.update()
print(f"tapered:{obj.name}")
```

**checklist**：要收尖的那圈顶点，是不是**先压到中线（x=y=0）再合并**？只按比例缩放一定得到平头。

## 坑四：headless 下慎用 `bpy.ops`（★ 能省掉很多"不明原因失败"）

`bpy.ops` 的很多算子是 **context 依赖**的：要求"当前是编辑模式 + 活动对象是它 + 有选择集 + 有合适的区域（VIEW_3D）"。
在 `blender -b`（无窗口、无区域）里这些前置条件经常不成立，于是你拿到的是
`RuntimeError: Operator bpy.ops.mesh.xxx.poll() failed, context is incorrect` 这种**看不出原因**的失败。

| 类别 | headless 表现 | 建议 |
|---|---|---|
| `primitive_*_add` | ✅ 稳 | 直接用 |
| `object.modifier_add` / `modifier_apply` | ✅ 基本稳（给 `view_layer.objects.active` 就好） | 直接用，apply 前设 active |
| `object.mode_set` + `mesh.*`（挤出/内插/环切/remove_doubles…） | ⚠ 常见 poll 失败 | **改 bmesh** |
| `mesh.loopcut_slide` / `transform.*` / `uv.*` | ⚠ 依赖区域/模态输入 | 不要用；用 bmesh 或直接改 data |
| `object.shade_smooth` / `object.select_all` | ⚠ 依赖 view_layer | 用 data API |

**替代写法（推荐）**：

```python
# 平坦/平滑着色：直接改面属性，不碰 ops
for p in obj.data.polygons:
    p.use_smooth = False        # 或 True

# 法线一致化：bmesh 版（等价 normals_make_consistent）
import bmesh
bm = bmesh.new()
bm.from_mesh(obj.data)
bmesh.ops.recalc_face_normals(bm, faces=bm.faces)
bm.to_mesh(obj.data)
bm.free()
obj.data.update()
```

必须用 ops 时：用 `bpy.context.temp_override(...)` 补齐 context，或者**改走 GUI 通道**。

**判据**：同一段脚本在 headless 报 poll/context 错、在 GUI 正常 → **就是这个坑**，不要去怀疑几何数据。

**checklist**：这段脚本里有 `object.mode_set` / `mesh.*` / `loopcut` / `transform.*` / `uv.*` 吗？有 ⇒ 改 bmesh 或 data API。

## 坑五：法线方向是一切"穿模 / 内含"判据的前提（★ 会给出反向结论）

任何形如 `(p − loc) · n < 0 → "在内部"` 的判据（点在内侧、件插进主体多深、面是否朝外），
**都假设法线朝外**。法线朝内时结论会**整体反号**。

> 实测：车体侧板外表面法线朝内 → 审计把"贴在外壁上的支架"误报成"深入车体 150 mm"。
> 这类错误最坑的地方是**它看起来像几何错了**，于是你去改几何，越改越乱。

### 纪律

1. 做任何穿模 / 内含判定**之前**，先验法线（用 `blender_gate.py -- normals`）。
2. 装配层**统一兜底**一次 `recalc_face_normals`，别指望每个 builder 都记得。
3. 判据写进报告时要带**法线前提**："在法线朝外的前提下，X 深入 Y 12 mm"。
4. **双向确认**：同一对件用"三角求交"与"逐轴 AABB"各跑一遍，结论相反就先查法线。
5. **`unknown` 不许当 pass。**

### ⚠ 聚合有符号体积会漏判（本门存在的主要理由）

`bm.calc_volume(signed=True)` 把**所有壳相加**：大正向壳（+8）+ 分离的小反向壳（−1）= +7 > 0
⇒ **反向的那块被吞掉**。

所以必须**逐连通壳**判。`blender_gate.py -- normals` 就是这个口径，且 selftest 里有一条
"大正向壳 + 分离小反向壳"的用例专门守这条（笨办法会漏判，逐壳能抓到）。

| 逐壳状态 | 含义 | 处置 |
|---|---|---|
| `pass` | 闭合、绕向一致、`signed_volume > 0`；合法嵌套空腔标 `nested` 豁免 | 记入回执 |
| `fail` | 至少一个**非嵌套**壳闭合、绕向一致、`signed_volume < 0` | 先 recalc 再复检 |
| `n/a` | 网格未闭合，"整体朝向"无意义 | 先闭合，或对有意的开口件只按口部法线单独核对 |

**未闭合的网格没有"整体朝向"这回事** —— 别把 `n/a` 读成"没问题"。

## 坑六：给 AI 用的预览装置，默认必须看得清几何突变

实测（三个组员都抱怨过）：白材质 + 白背景的预览图**"白对白"**，板缝、焊缝、分块全看不见，
根本没法 QC —— 最后是组员自己改成"**灰材质 + 单侧强太阳**"才看清。

**默认就该这么配**（写进你的预览函数，而不是每次临时调）：

- **材质**：中性灰（`Base Color ≈ 0.18`、`Roughness ≈ 0.6`、`Metallic = 0`），**不要纯白**；
- **光照**：**单侧强太阳**（斜 45°，`angle ≈ 1–3°` 的硬阴影）+ 很弱的环境光 —— 硬阴影能把 1–2 mm 的台阶照出来；
- **背景**：中灰或渐变，别用纯白 / 纯黑（前者吃掉高光，后者吃掉暗部）；
- **零件级 QC**：逐部件配色 + 图例，比"整体一个灰"更容易发现"少了一块 / 装反了"；
- **每次至少两个机位**：一个"英雄机位"（像不像）+ 一个"斜 45° 检查位"（缝、浮空、穿模）。

**判据**：**如果一张图看不出板缝在哪，这张图就不能作为 QC 证据。**

## 坑七：启发式判据把"遮挡"判成"埋住"，还会整片误杀（★ 2026-11 实测，路灯用例发现）

`-- buried` 的口径是"从面中心沿外法线打射线，命中别的几何就算埋住"。
它抓得住"join 两个重叠立方体"这类真内部面，但**分不清"被挡住"和"埋在实体里"**。

实测对象：一盏中世纪铸铁路灯（单体水密实体，948 顶点 / 848 面 / **1 个连通壳**，其余五道门全 pass）。
`buried` 报 **144 / 848**。逐张定位：

| 位置 | 张数 | 朝向 | 命中了什么 |
|---|---|---|---|
| 底座台肩 z=0.20 | 16 | +Z | 2050 mm 上方的上环箍 |
| 灯座托盘下表面 z=2.20 | 16 | −Z | 2050 mm 下方的底座 |
| 托盘上表面 z=2.30 | 32 | +Z | 288–618 mm 上方的屋顶 / 竖梃 |
| 竖梃内侧 z=2.40 / 2.70 | 16 | 径向 | 正对面竖梃（318 mm） |
| 中箍 / 屋顶内侧 | 64 | ±Z / 径向 | 对面的箍与托盘 |

全部是**看得见的凹腔面**。

### 为什么这不是"模型问题"

**闭合流形的单壳网格在数学上不可能含内部面** —— 每个面都在体积边界上。
所以对这类网格，`buried > 0` **恒为遮挡**，不可能是缺陷。
（`buried` 真正要抓的是"多壳互相埋入"，那种情况一定伴随 ≥2 个壳。）

### 正确判据

1. **闭合 + 单壳 ⇒ 定理判 0**，不要拿射线去猜；
2. **多壳 ⇒ 逐壳做壳间包含检测**：A 的面中心是否落在**其他壳**的体积内；
   射线只打别的壳 —— 顺带避开"面正下方 0.3 mm 近切向命中"的数值坑。

> ⚠ 第一版用"面中心沿法线外移 0.3 mm + 奇偶交点法"打整张网格的 BVH，
> 在**单壳**上误报出 9 张"真内部面"。近切向命中会让奇偶翻转。
> 这就是"射线要打别的壳、不要打自己"的来由。

实现：`tools/blender_buried_true.py`（工作区 `tools/`，自带 selftest）。

### 新门必须自带对拍用例

| 用例 | 启发式 | 真判据 | 期望 |
|---|---|---|---|
| clean cube | 0 | 0 | pass |
| 两个重叠立方体 join | >0 | >0 | **fail**（该抓的必须抓到） |
| 闭合环形筒（凹腔） | >0 | 0 | **pass**（不该抓的不能误杀） |

**只有三态都对拍过，才允许用它的判决覆盖原门。** "启发式报 fail 就手工改判 pass"是禁止动作。

## 坑八：贴图「节点在 ≠ 可用」——三层都踩过（★ 2026-11 用户实测打回两次）

同一个"贴图未引用 / UV 不可用"的反馈，背后是三层独立缺陷，必须逐层用门挡住：

### ① 有 `TEX_IMAGE` 节点，但没有 UV 层

材质里节点齐、`check_materials` 判 pass，渲染出来**整灯一片死色** —— 采样永远落在同一个纹素上。
**契约门必须硬判 UV 层存在且未退化成单点。**

### ② 有 UV 层，但那是"投影"，不是"展开"

补了 UV 仍不合格。箱式三平面投影的 UV：层存在、不退化、`check_uvs` 判 pass，
但 6 套投影面**全叠在同一 UV 空间**——实测面级包围盒重叠 **2001 对**、UV 范围 `[-0.25, 4.0]`。

> **只有配无缝平铺贴图才"看起来没事"。** 烘焙 / AO / 光照贴图 / 非平铺贴图全部不可用，
> UV 编辑器里也一片糊。这类缺陷看图看不出来，必须机械判。

柱面投影同样不合格：水平面（灯座托盘顶面）被压成一条线，渲染出条纹。

**正确做法：分岛展开 + 装箱**（纯 data API，不碰 `bpy.ops.uv.*`）

1. 按面主法线分 6 桶（±X/±Y/±Z）——不分桶的话整根圆柱会被摊成一个岛，严重拉伸；
2. 桶内按边连通分岛；
3. 每岛平面投影；
4. 按 3D 面积统一 texel density（每岛缩放使 `uv_area ∝ world_area`）；
5. shelf 装箱进 [0,1]²，**二分搜索最大的全局缩放 k**。

实测（铸铁路灯，848 面）：102 岛 / 岛间重叠 **0** / 覆盖率 43% / texel 密度比 **1.0002** / UV 全在 [0,1]²。

**判据**（`blender_uv_gate.py`，selftest 6 例）：
有 UV 层 + 无退化面 + 全在 [0,1]² + **岛间包围盒不重叠** + 覆盖率 ≥ 15% + 密度比 ≤ 1.10。
岛按 **UV 空间**重新推导（共享边两侧 UV 一致 ⇒ 同岛），**不信展开时的中间结果**。

**视觉证据**：给模型套 UV 棋盘整张渲染，格子必须**等大、不拉伸、无重叠**。
`renders/lamp-uv-checker.png` 就是这个证据。

### ③ 材质引用链不完整

三件缺一就会出现"贴图未引用"：

- 纹理节点 **Vector 口显式接 `UVMap` 节点**（不能靠隐式默认 UV）；
- 图 **pack 进 `.blend`**（**先 `pack()` 再改相对路径**；反过来时 `.blend` 尚未存盘，
  `//x.jpg` 会解析到盘符根并报 `source path not found` —— 实测）；
- 贴图文件名与 FBX **同名后缀** `<stem>_basecolor.jpg`，Unity 侧才找得到。

## 坑九：Boolean `TRANSFER` 会搬进空材质槽

`bpy.ops.object.modifier_apply` 应用 BOOLEAN 时，`material_mode` 默认 `TRANSFER`：
**操作数的材质槽会被搬进目标网格**。操作数若没有材质，搬进去的就是 `None` 空槽，
再 `materials.append(mat)` 之后网格上就有两个槽 —— Unity 会据此多生成一个 submesh 并留下未指定材质的槽。

处置：

```python
me.materials.clear()
for p in me.polygons:
    p.material_index = 0
# 再赋唯一材质；末尾断言 len(me.materials) == 1
```
