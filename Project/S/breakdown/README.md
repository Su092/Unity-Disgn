# 开发拆解 — S

本目录存放「按 `docs/` 拆出的可执行开发切片」。实现时只改本游戏 `unity/` 工程。

## 使用方式

1. 确认 `docs/` 中对应规格已写清（配件看 `loadout-spec.md`，环境看 `gameplay-spec.md`）
2. 在本目录新增或覆盖任务文件（`NN-主题.md`）
3. 任务文件必须含：目标、依据文档、改动路径、验收
4. 完成后更新 `../memory/CURRENT.md` 的状态

## 推荐执行顺序与理由

```
03（✅预览） → 02（✅箱庭+Boss） → 04-art（✅模型+贴图） → 06（✅UI） → 04-pres（✅音效/材质/后处理） → 05（✅首轮校准） → 03 剩余
```

| 序 | 切片 | 为什么排这个位置 |
|----|------|------------------|
| 1 | **03 拖拽落点预览** ✅ | 「顺序即解法」是本作唯一的核心技能。规则若不靠 UI 教，等于没传达。**已完成** |
| 2 | **02 箱庭 + Boss** ✅ | 威胁值机制的前提是「区域之间有推进成本」。单平面上威胁值只是数字。**已完成** |
| 3 | **04-art 模型+贴图** ✅ | 灰盒换真资产，才能判断场景精致度是否达标。**已完成** |
| 4 | **06 UI 素材** ✅ | 场景定稿后再做 UI 换皮，避免配色反复。**已完成** |
| 5 | **04-pres 音效/特效** ✅ | 需要模型才能挂特效锚点。**已完成** |
| 6 | **05 校准** ✅ | 数值要在完整内容上校准才有意义。**首轮已完成**（单体极差 2.25× → 1.21×） |
| 7 | **03 剩余**（方案存档 / 扩件） | 扩件会让数值面变大，必须在校准之后 |
