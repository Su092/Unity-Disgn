# 任务 09：自动驾驶跑局（AI 采样）

- 状态：**完成**（2026-11-12）
- 依据：`docs/calibration-log.md`「待校准」

## 目的

`07-telemetry.md` 的遥测要「人玩一局」才能出数据。人工成本高、且无法反复跑同条件。
本任务让 **AI 用与真人相同的输入管线**自己玩一局，产出可信的节奏数据。

用法：

```powershell
& "E:\S\Build\Windows\S.exe" -autoplay -screen-width 1600 -screen-height 900 -screen-fullscreen 0
# 产物：E:\S\autoplay.log（含遥测详情与最终构筑）
```

## 实现要点

| 项 | 做法 |
|----|------|
| 输入来源 | `PlayerController.AiControlled = true` 后走 `UpdateAi()`，与真人共用移动/冲刺/跳跃/重力管线 |
| 瞄准 | 把目标方向转成 yaw/pitch 增量，单帧上限 25°（模拟人类转头） |
| 走位 | 保持 8–18m；太近后撤、太远接近、其余侧移（每 1.2s 换向） |
| 开火 | 对准（±12°）即扣扳机，走与玩家相同的 `GunRuntime.TryFire` |
| 升级 | 有 offer 选第一个；背包件自动装进空链（衍生件插链首以保证后继作用域生效） |
| 进区 | 本区清空后走向门洞 |
| 保护 | 900 秒硬上限，防 AI 卡死无限跑 |

## 关键收获：跑出了 4 个真实 bug

AI 第一次跑只活了 **2.5 秒**，之后每次排查都暴露一个玩家同样会遇到的问题：

### 1. `FindNearestEnemy` 在遍历中清理导致漏检

```csharp
// 错误：同一个循环里既 RemoveAt 又继续比较
for (int i = _enemies.Count - 1; i >= 0; i--)
    if (e == null || !e.Alive) { _enemies.RemoveAt(i); continue; }
```

现象：`enemies=2` 但查找返回 null，AI 僵持 **60 秒**不动，区域永远清不完。
修法：清理与查找分成两个循环。

### 2. 敌人贴到 0.1m 把玩家挤住

现象：`d=0.1m`，玩家 `CharacterController` 被敌人堵住无法后退，只能原地挨打，
**4 只贴身 2 秒杀满血玩家**。
修法：敌人与玩家保持 0.9m 最小间距（每帧推开）。

### 3. `normalized` 在距离≈0 时产生 NaN，把敌人推到 9101 米外

现象：日志出现 `dist=9101.6m`，而同一敌人的 `LIST` 报告位置是 `(0,0,-11)`。
NaN 写进 `CharacterController.Move` 后位置直接崩坏，之后**再也找不回**。
修法：① `Move()` 里拒绝 NaN/Infinity；② 完全重合时用固定侧向推力；
③ 越界敌人（离区域中心超过 1.5 倍区域尺寸）直接回收。

### 4. 爬行者速度 6.0 高于玩家步行 5.6

现象：玩家永远跑不掉，贴身即无解。
修法：降到 **5.2**（能拉开距离，但仍会持续逼近）。

### 附带调整

`player.iFrames` 0.25 → **0.40**：接触伤害 12 配合 0.25s 无敌 = 48 DPS，
4 只贴身时仍然过快。0.4s 把上限压到 30 DPS。

## 修复前后对比（同一 AI）

## 首轮节奏数据（修复后）

| 指标 | 实测 | 设计目标 | 判定 |
|------|------|----------|------|
| 区域 1 清空 | 25.4s / 威胁 7 | — | 略快 |
| 区域 2 清空 | 47.1s / 威胁 19 | 每区 +10–20 | **符合** |
| 到达等级（77s） | 9 | 12–15（一局） | 比例合理 |
| 三选一 | 8 次 | 14–16 | 同比例 |

**结论**：战斗节奏基本符合设计；**背包容量 24 明显过多**，玩家几乎不需要管理空间。
