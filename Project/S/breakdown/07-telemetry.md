# 任务 07：对局遥测（把手感变成数字）

- 状态：**完成**（2026-11-12）
- 依据：`docs/gameplay-spec.md` §4 §5 §6、`docs/calibration-log.md`「待校准」

## 为什么做这个

校准日志里剩三项「只能真人验证」：

| 项 | 原来的判断方式 |
|----|----------------|
| 威胁值节奏 | 「加压感够不够」 |
| 敌人血量手感 | 「爬行者几发打死」 |
| 背包容量 24 | 「会不会频繁背包满」 |

这三项靠感觉说「太快/太慢」无法定位。所以做一个**局内采样器**：
玩家正常玩一局，结束时自动生成报告，拿数字来校准。

## 采样内容

| 指标 | 采样点 | 用来判断 |
|------|--------|----------|
| 威胁值曲线 | 每 5 秒一点 | 增长是否过慢/过快、清区回落的幅度 |
| 区域清空快照 | 每次清区 | 每区结束时的威胁与击杀数（对比设计值） |
| 敌人击杀耗时 | 每只敌人「生成 → 死亡」 | 各类敌人的 TTK 是否合理 |
| 背包使用 | 每次开关 + 峰值占用 | 是否频繁满、总时长是否超预算 |
| 三选一次数 | 每次抽卡 | 是否落在 14–16 次设计区间 |

## 产物位置

```
C:\Users\<用户>\AppData\LocalLow\S Project\ProjectS\run-telemetry.txt
```

每次结算（通关或死亡）覆盖写入。**自检模式不写**，避免污染真实数据。

## 判据（拿到数据后照着看）

| 指标 | 健康区间 | 偏离时改什么 |
|------|----------|--------------|
| 一局总时长 | 25–35 分钟 | 波次数量 / 敌人数量 |
| 到达等级 | 12–15 | 敌人 XP（改 XP 不改曲线） |
| 三选一次数 | 14–16 | 同上 |
| 清区时威胁 | 每区比初值高 10–20 | `ThreatTick` 的 1.2/s 与击杀 0.4 |
| 背包占用峰值 | ≤ 20/24 | 提高容量或降掉落频率 |
| 背包总时长占比 | ≤ 25% | 拖拽摩擦 / 筛选效率 |
| Crawler TTK | 1–3 秒 | 爬行者 HP（当前 60） |
| Shield TTK | 5–8 秒 | 盾卫 HP（当前 140） |

## 注意

- 遥测只在**正常游玩**时启用；自检里手动开启后测完会删掉报告文件
- 报告是覆盖写入，不累积历史（如需对比多次，手动复制一份）
- 采样间隔 5 秒：一局约 370 个点，报告不会过大
