使用 blender-director 流程，为 Unity 第一人称生存构筑游戏制作第一张完整地图「鸣奏大剧院」。

这是一座能够实际进入、穿行、上下楼和战斗的完整室内大剧院。交付物必须同时包括可复用的模块化环境套件、完整拼装场景和导出资料，不能只做单个舞台、背景立面、模块陈列、概念渲染或从一个角度成立的摄影棚。

## 1. Production Brief

- 类型：完整室内箱庭关卡 + 模块化环境套件，目标 PC / Unity 6000.6.4f1 / URP。
- 主题：古典乐器、剧院演出、音律幻想。场景名「鸣奏大剧院」为制作暂名，不需要写成巨大场景文字。
- 风格：参考 02 的复古日本动画美术、赛璐璐明暗分块、手绘质感、清楚的建筑轮廓。将参考中的露天建筑语言转为完整室内剧院。
- 核心空间：门厅、一楼观众厅、表演台、左右侧台、后台、左右侧廊、可到达的二楼回廊与包厢、四处上下楼交通。
- 地图尺度：建议总外轮廓约 64m × 72m；一楼主要地坪 Y=0；舞台 Y=1.2m；二楼地坪 Y=6m；大厅屋顶内侧约 Y=18m。尺寸是建模起点，可为结构和通行作局部调整，但必须同步图纸与清单。
- 模块网格：主结构 4m；允许 2m、1m 补件；细定位 0.25m。楼梯踏步、花纹等细节可脱离该网格，结构端点必须回到网格。
- 单位：1 单位 = 1m。以 1.75m 人形、1.65m 视点及直径 1m / 高 2m 通行检查胶囊作为建模尺度参考；接入时再核对游戏真实控制器。
- 面数：普通模块 LOD0 300–3500 tris；平面、简单板件不必凑面数。完整管风琴、吊灯、舞台拱框应拆成复用子模块，不能把一个高模总成算作普通模块规避预算。
- 贴图：共享 1024 平铺材质 + 1024 Trim Sheet，约 256px/m；4m 对应一轮 1024 纹理。可用约 6–8 套共享材质，不给每把椅子或每段墙独占贴图。
- LOD：普通模块建立 LOD0 / LOD1；LOD1 以 LOD0 的 40%–60% 为目标；低面简单结构允许保留必要拓扑并报告例外。
- 导出：FBX、独立 PNG 贴图、可编辑 .blend、布局清单、模块清单、碰撞清单、预览图与验证报告。
- 工作目录：`<GAME:S>/_Inbox/Environment/GrandTheater`。执行前将路径记号解析为当前机器工程目录；不要覆盖旧铸造场交付。

建议依次使用 blender-director → environment-artist → anime-style → scene-assembly → uv-workflow / materials → lighting → asset-optimization → lod-pipeline → collision-proxy → unity-export → qa-review。先写 Reference Analysis 和 Production Brief，再做灰盒与连通检查，最后进入精细建模。

## 2. 美术设计

剧院具有「演出即将开始，音乐魔法苏醒」的气氛。建筑完整、庄重、带轻微使用痕迹，不以破败恐怖为主。

- 象牙白与浅暖灰墙面、午夜蓝阴影、酒红或暗紫红帷幕、温暖木地板、哑光金色装饰。
- 两到四档主要明暗；阴影边界明确。木纹、布料和墙面变化适度，避免密集噪点与写实脏污。
- 金色用于柱头、栏杆、舞台框和少量花纹；不将整面墙做成强反射金属。
- 建筑节奏来自重复拱券、壁柱、观众席与包厢，不把每面墙贴满音符。
- 主要音乐识别来自舞台管风琴、乐谱架、琴架、乐器箱、帷幕和少量五线谱/琴弦式装饰。
- 舞台是最强视觉焦点，二楼拱廊是第二层轮廓。过道和楼梯入口明亮可辨。
- 采用暖琥珀舞台主光、适量冷蓝环境补光。室内窗可以透光，但外面仅为不可达背景。
- 屋顶、穹顶和墙体完整闭合；不存在露天院落、屋顶大破洞或大片裸露天空。
- 参考图中的人物、敌人、手持乐器、弹道与 HUD 不属于本次建模范围。

## 3. 空间布局与定位

以下坐标均为导入 Unity 后坐标：+Y 向上，+Z 朝舞台，X 为左右；原点位于一楼大厅基准中心。Blender 内部坐标由导出过程统一转换。

建议地图边界 X=-32…32，Z=-36…36。按以下分区搭建：

|---|---|---|

| 主观众厅 | X=-24…24，Z=-24…12 | 中央开阔走道、分组观众席、横向穿行通道，可从后场清楚看到舞台 |

| 左右侧台 | 舞台左右各约 10m 宽 | 连接观众厅、舞台、后台，提供绕行及局部遮挡 |

## 4. 通行与第一人称战斗要求

先让建筑能完整走通，再添加装饰。

1. 一楼至少形成「后场 → 左侧廊 → 台前 → 右侧廊 → 后场」与「左侧台 → 后台 → 右侧台 → 台前」两条闭合环路。
2. 二楼有连续可走地板、栏杆、真实楼梯开口和连接廊；四处楼梯均能从一楼走到二楼并返回，不靠跳跃、传送或隐藏入口。
3. 楼梯建议采用折返双跑，每级高 0.15m、踏面约 0.32m；6m 高差为 40 级，可分两跑各 20 级。单跑净宽约 3m，平台净深不小于 2m，楼梯间参考占地 8×12m。最终以实际净高和转身空间检查为准。
4. 楼梯上方楼板必须开洞，不得出现最后几级撞楼板、头部撞梁、平台与回廊高度不一致等问题。全程净高至少 2.8m。
5. 舞台左右前侧各有宽台阶；两侧台另有与一楼相通的缓坡或后侧入口。舞台、侧台、后台均可自然往返，不是隔离平台。
6. 主通道 5–8m，次通道不小于 3m，主要门洞净宽不小于 3m、净高不小于 3.5m。视觉尺寸不算净宽，柱脚和装饰占用必须扣除。
7. 观众席按岛状分组，每组保留前后横道；中央走道建议约 8m。不能用密排椅子堵成狭窄影院迷宫。
8. 桌椅、矮隔墙、厚实乐器箱形成少量遮挡和路线变化；禁止在主道随机散布小石块、线缆、不可见台阶等绊脚物。
9. 二楼栏杆高约 1.05–1.15m，厚实底座和稀疏上部杆件兼顾安全与向下观察。可见空隙不能使用整块射击碰撞面封死。
10. 回廊边缘有可见护栏，地图边界由实体墙或合理关闭的门形成；不用空气墙代替缺失建筑。
11. 二楼地板、栏杆、上楼开口与桥廊必须从下方和侧面也成立，不能从一楼看到楼板背面消失。
12. 包厢用双入口或连通前后廊接入环路，避免大型单入口死胡同。纯装饰不可进入空间需通过真实关闭的门或墙明确表达。
13. 不建深乐池、强制落坑、单向高落差路线及不可返回的观演平台。
14. 除建筑自然结构外，不继承旧地图 Boss 台、能量柱、科幻机关、电池、工厂设施及其摆位。表演台是剧院本身的空间，不预设任何 Boss 专用功能。

目标约 55–75 种基础模块，数量可随合并复用调整；重复物体使用实例，共用网格和材质。

吊灯最低点应避开所有玩家通行与二楼观察线；不能在准心常用高度悬挂过多吊饰。暂不制作会动的建筑机关、复杂布料动画或破坏系统。

## 6. UV、材质与灯光

- UV0 适配平铺和 Trim；统一密度，曲面与端头避免明显拉伸。
- UV1 为可用于 Unity 烘焙的非重叠光照 UV，足够间距；不要把平铺 UV0 直接当光照 UV。
- 木材、象牙白墙、红色织物、深蓝饰板、哑金装饰、灰石地面使用共享材质；材质名统一 MAT_Theater_*。
- 每模块尽量 1–2 个材质槽，复杂主视觉总成允许适量增加并记录。
- 提供 BaseColor、必要的切线空间 Normal，以及明确通道定义的 Mask。若采用项目现有约定，Mask 为 R=Metallic / G=AO / B=0 / A=Smoothness；颜色贴图 sRGB，其余线性。
- 动漫风格不能依靠 Blender 专属节点渲染后就当作 Unity 可用。保留可迁移的颜色/遮罩资料并记录 Toon 分段参数；无 Unity Toon 支持时需明确记录近似还原差异。
- 只在必要轮廓使用描边，避免每个椅子、栏杆、管风琴细管都有粗黑边导致画面发黑。
- 主光方向统一；舞台暖，观众厅冷暖平衡。门厅和后台允许更暗，但不允许关键通道全黑。
- 控制透明叠层、体积光、Bloom 和大量实时投影灯。气氛不能遮住敌人轮廓或通行入口。
- 灯光对象独立于静态几何。Blender 演示灯光不假定经 FBX 自动变成 Unity 最终效果，应另交参数表。

## 7. 碰撞与导出

碰撞体单独放 COL_Collision，禁止渲染；每个代理明确关联可见模块，并注明 Movement / Shot / Both 用途。

- 地板、墙体、厚柱、厚掩体的代理贴合可见几何。
- 门洞用左右柱和上梁分件碰撞，不能拿整块盒子包住门洞。
- 楼梯提供平滑移动坡面以及实际台阶射击代理；导入端分别配置查询/碰撞图层。射击不能打中用于移动的空气坡面。
- 有孔栏杆、拱门、管风琴间隙和帷幕开口的射击代理应保留可见空隙。
- 可见布帘与小饰物可以无碰撞，但必须明确标注，不能用大盒子兜住整组装饰。
- 不用世界坐标 AABB 直接替代旋转/弧形模块的碰撞，避免模型旁边出现空气阻挡。
- 普通移动接触面偏差目标不超过 3cm；射线抽样中无可见遮挡却提前超过 6cm 命中的情况应为零，例外必须定位解释。
- 二楼楼板、楼梯平台、坡道和舞台之间无可跌落细缝；碰撞必须与最终放置变换一起检查。

COL_Layout、COL_Modular_Geo、COL_SetDressing、COL_Lights、COL_Cameras、COL_Collision、COL_Ref 分组明确。模块命名 SM_Theater_[Type]_[Variant]_LOD0 / LOD1；拼装根节点 GrandTheater。

Blender 使用米制及自身 Z 向上坐标；最终导入 Unity 必须 +Y 向上、+Z 朝舞台。先用 1m 标尺、方向箭头、非对称测试模块验证坐标、手性、旋转和缩放，再批量导出。不要靠所有实例负缩放或反复补 90° 来掩盖导出问题。

地面和平台拼接基准取顶面基准角；墙体取底角；道具取底部中心；转角与特殊曲面在清单注明原点。应用必要变换后保持可预期的正缩放。贴图与 FBX 分离交付。

建议地图静态几何全实例 LOD0 总量目标不高于约 45 万 tris，常见视角可见量目标约 30 万 tris 内；这是优化目标，不是已测性能结论。优先共享网格、材质和实例，完整场景不要合并成一个无法剔除的巨型 Mesh。

## 9. 验收步骤

1. 灰盒先给一楼平面、二楼平面、穿过楼梯的剖面，标注实际净宽/净高、地坪高度及闭合路线。
2. 以玩家约 1.65m 视高检视：进入门厅、观众厅后排看舞台、台上回望、二楼俯看、后台向侧台看。不能只用俯视大图验收。
3. 显示屋顶与隐藏屋顶分别检查：完整内部空间正常；隐藏仅用于平面审阅，最终场景屋顶完整存在。
4. 实走四处楼梯双向、两侧上台路径、一楼与二楼完整环路；逐一记录成功/失败，不能只用相邻节点距离推断可达。
5. 碰撞叠加检查门洞、栏杆空隙、楼梯、拱门、台口边缘。对可见空隙和实体表面分别做射线检查。
