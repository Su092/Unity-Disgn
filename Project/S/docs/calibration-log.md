## 2026-11-12 首轮校准（三枪时代，已归档）

> **本节描述的是三枪（连发 / 榴弹 / 单发）时期的数据，现已不适用。**
> 保留它是因为「测量方法的三次翻车」和「`m_blast` 抹平武器定位」这两个教训，
> 换到六枪后仍然成立。**当前基线见 §2026-11-16。**

### 方法

新增 `tools/loadout-tests` 的两个基准入口：

```powershell
cd "<GAME:S>\tools\loadout-tests"
dotnet run -c Release -- -bench     # DPS 基准 + 经验曲线
```

`DpsBench` 用**蒙特卡洛弹道模拟**算实际命中率，不用纸面公式：

- 目标：半径 0.5m 的球（敌人躯干近似），20m 距离
- 每颗弹丸在散射锥内均匀取偏移，检查轨迹与目标的最近距离
- 存在时间到期未命中 = 未命中
- 榴弹走抛射（含重力）

**为什么必须模拟**：霰粒散射 +3°、分裂后每颗再 +2°，纸面 DPS 会高估一个量级。
当时实测「分裂+霰粒」链：纸面 85.0 → 实测 18.8（命中率仅 22.1%）。

### 测量方法的三次翻车

| # | bug | 现象 | 修正 |
|---|-----|------|------|
| 1 | 弹道采样按「生命周期均匀分 48 步」 | 单发枪（140m/s × 1.2s = 168m 射程）每步跨 3.5m，而目标球只 1m → **命中率算成 0%** | 改为按距离自适应步长（5cm） |
| 2 | 多目标场景朝正前方盲射、目标随机散布 | 命中率近 0，看似「武器全废」 | 改为瞄准最近目标（真实玩家会瞄准） |
| 3 | 榴弹（有重力）混进直线命中率统计 | 抛射物按直线算必然 0% → 差点把榴弹当废枪改数值 | `Bench.SimulateHitRate` 里 `if (p.Gravity > 0f) continue;` 直接跳过 |

第 1 个 bug 特别值得记：它让「单发枪 DPS = 0」，如果不是我怀疑测量方法而是直接改数值，
会把一把正常的枪改成怪物。第 3 个同理，**这次是测量口径本身写错，不是枪弱**。

### 校准前后对比（单体，20m，三枪时代）

| 档位 | 校准前 | 校准后 |
|------|--------|--------|
| 裸弹 | 连发 60.4 / 榴弹 26.9 / 单发 34.2 = **2.25×** | 连发 60.4 / 榴弹 51.3 / 单发 62.3 = **1.21×** |
| 浅构筑 | 121.9 / 54.3 / 68.9 = **2.25×** | 121.9 / 103.5 / 125.6 = **1.21×** |
| 深构筑 | 181.7 / 88.9 / 102.8 = **2.04×** | 181.7 / 148.1 / 187.2 = **1.26×** |

判据是「极差 ≤1.30×」。**这个判据在六枪时代已作废**——6 把枪的射速跨越 0.06~0.85 s、
读取数 1~2、槽位 6~12，强行拉平会毁掉「槽位多 = 能塞复杂连锁」这个设计支点。
现在的判据是「没有哪把枪是废的」（裸弹 DPS 极差 ≤6×，见 `Bench.CheckNakedFloor`）。

### `m_blast` 单独说明（结论仍然有效）

初版是「溅射 +1.6m / 伤害 ×1.25」。实测发现它让**单发枪群伤从 68 涨到 161（2.4 倍）**，
而榴弹枪本职群伤是 170 —— 一个史诗配件几乎抹平了武器定位差异。

降为「+1.4 / ×1.00」后层级恢复。它仍然是史诗（溅射对单体链是质变），但不再能替代榴弹枪。

> 六枪时代 `m_blast` 已按新字段体系重写（`explodeRAdd` / `explodeRBase` /
> `explodeDmgFlat` / `explodeDmgFromDmg`），ID 也改成了 `explode`。**设计意图不变**：
> 群伤是榴弹枪的本职，配件只能加强、不能替代。

## 2026-11-15 单图时间轴改造（结构变更，非数值校准）

本轮改的是**节奏结构**，不是武器数值。

### 改了什么

| 项 | 旧 | 新 | 依据 |
|----|----|----|------|
| 场地 | 6 区 ×（34×44）串联 | **1 张 100×100** | 6 段重复暖场，真正高压只占 1/3 |
| 节奏来源 | 区域推进 | **存活时间**（`RunDirector`） | 让「还剩多久」可被玩家计算 |
| 威胁 | 秒 +1.2 / 击杀 +0.4，清区 −25 | `100 × t / 600`，无泄压阀 | 无限刷怪下击杀项会爆表，且惩罚快速清场 |
| 威胁满 | 无明确终点 | **10:00 与 Boss 对齐** | 「变到最硬」与「Boss 出场」应是同一件事 |
| 敌HP缩放 | `1 + 0.004 × threat` | `1 + 0.008 × threat` | 无清区泄压阀，原斜率在 8 分钟只让敌人硬 40%，终局检验不足 |
| 敌伤缩放 | `1 + 0.0025 × threat` | `1 + 0.004 × threat` | 同上 |
| 精英 | 威胁 ≥35 的最后一波 | **5:00 / 6:30 / 8:00 / 9:30 共 4 只** | 与威胁脱钩，让遇见精英可预期 |
| 经验来源 | 击杀 + 清区 15% | **只有击杀** | 清场效率应直接等于构筑速度 |
| 单局时长 | 25–35 分钟 | **11–14 分钟** | 配件深度要在一次坐下里看到成效 |

### 没有调的（以及为什么）

- **22 件衍生件的数值一分未动**：从三枪迁到六枪时只改了 ID 与字段体系
  （`m_blast` → `explode`、`m_split` 移除等），效果强度保持原样。
- **等级曲线 `need(L) = 2L² + 5L + 8`**：未动。它决定升级频率，与枪数无关。
- **背包容量 44**：未动（旧文档写过 24，那是三枪时代的预估值）。

**为什么不一起调**：六枪重制同时改了枪数、件的字段体系、作用域种类三件事。
在这种规模的结构变更里再动数值，实测数据无法归因。**先定结构，再调数值。**
