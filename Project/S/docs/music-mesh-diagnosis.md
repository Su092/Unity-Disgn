# 音律敌人网格拉伸诊断（2026-11-19）

> 状态更新：本问题现已修复并重建验证，见 [修复与验收记录](music-mesh-fix.md)。以下为修复前诊断记录。

## 已确认根因
原始 08 FBX 在相同 Sweep_Windup、0.675s 姿态下正常，正式预制体出现用户截图中的身体与手臂拉面。问题发生在入库更新阶段，不是本次原始 08 建模文件的异常。

`SMusicEnemyImporter.Save<T>` 对已有 Mesh 调用 `EditorUtility.CopySerialized`。在本批网格上，这个覆盖操作没有完整替换顶点/索引缓冲，仍保留旧几何数据；重建预制体却使用了本次的骨骼顺序和绑定信息，造成混用。独立内存复制实验复现：目标为 12832 顶点旧合并网格，源为 228 顶点原始分件，CopySerialized 后目标仍为 12832 顶点。实验只修改临时克隆，不写正式资产。

原生化前后不是新的两套美术结果：原生化阶段继承了已经错误的合并网格，所以“递归无 FBX 依赖”检查仍能通过。`SMusicNativeAssets.Extract` 和补件导入器的通用 Save 也使用相同复制方式，修复时应统一处理，避免以后重新导出再发生。

## 为什么旧验收没拦住
此前的 814 项资产检查和 Play 检查主要关注尺寸、动作能否绑定/播放、时长、命中和生命周期；原生资源检查关注依赖关系。缺少“新源与合并网格拓扑/权重一致”及动画形变后的几何比较，不能据此保证画面正确。之前整批模型验收结论需要撤回到“6 种敌人合并网格待修复”。
