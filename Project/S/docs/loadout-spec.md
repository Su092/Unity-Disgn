# 配件系统规格 — S（核心系统）

本文件是**唯一权威**的配件规则与数值定义。`gameplay-spec.md` 只引用不重复。

## 1. 结构总览

```
枪 Gun
├─ 固有属性：slotCount（配件位数）、fireInterval（击发间隔）、magSize（弹匣）、reloadTime、投射物基础行为
└─ 配件位 Slot × N
   └─ 施法链 Chain（有序，最长 6 项）
      ├─ 子弹配件 Bullet   ── 定义投射物本体
      └─ 衍生配件 Modifier ── 修正投射物或枪械
```

**一次开枪 = 一次施法**：轮转取一个配件位，把该位的链解析成一组投射物，扣一次弹药。

### 1.1 为什么是「轮转」而不是「同时全开」

沿用 Noita 非乱序法杖的施法序列：枪有 N 个位，每次扣扳机施放**一个**位，指针后移。3 位连发枪 = 3 发一轮循环。

- 位多 ≠ 更强，位多 = **能编排更多不同的花招**，代价是每一发都只用到整把枪的 1/N。
- 单发枪只有 1 位，等于把全部资源压进同一条链 —— 这就是「单发枪玩一刀流」的结构性理由。

**轮转规则**

| 项 | 规则 |
|----|------|
| 指针 | 每把枪一个 `cursor`，初始 0，**换弹不重置** |
| 取位 | 从 `cursor` 起找第一个**链非空**的位；全空则扣扳机只响空枪，不耗弹药 |
| 前进 | `cursor = (施放的位 + 1) % slotCount` |
| 空位 | 空位不施放、不耗弹药，轮转直接跳过 |

UI 必须始终显示轮转序列条（`1→2→3` 加当前指针高亮），否则玩家无法理解为什么每一发不一样。

### 1.2 链式逐渐触发（2026-11-13 变更，覆盖原「一次性结算」表现）

**规则的数值结论不变，变的是"什么时候发生"**：一次施法不再把整条链的全部投射物同时铺在枪口，
而是**沿链顺序逐项触发**，相邻两项间隔 = 该枪的 `fireInterval`。

| 项 | 规则 |
|----|------|
| 时间轴 | 链上第 `i` 项（0 起）在 `i × fireInterval` 时刻触发 |
| 子弹件触发 | 此刻生成它的投射物（先补算"此前已触发且按作用域作用于它"的配件） |
| 衍生件触发 | 作用到**此刻仍存活**的投射物；对其后生成的子弹，在其生成时补算 |
| 作用域 | `全场` 作用到那时在场的全部；`后继` 只作用到 `sourceIndex ≥ 触发时已出现子弹数` |
| 枪械件 | 不占时间轴（装配时改枪，不参与逐项触发） |
| 总伤害 | **必须等于**一次性全量结算的期望值（§3 的 ctx 在触发开始时就含全部子弹） |

**为什么必须"对后生成的子弹也生效"**：§3 的结算域里，链内所有子弹在第一步就都在 `ctx` 里了。
若运行时只改"此刻已经在飞的"实例，`[校准套件, 制式弹]` 这种最常见的链就会少算一段 ——
总伤害低于 HUD 显示的期望值，界面上就开始骗人。

实现分两路、合起来等价于全量结算：

1. 子弹生成时，补上"在它之前触发、且按作用域确实作用于它"的配件（按链顺序逐件施加）；
2. 之后触发的配件，再实时改当时在场的实例（`Projectile.ApplyDesc` 就地改，不重建）。

两条路径施加到每颗粒子上的配件序列与全量结算**完全相同（含顺序）**，因此总量必然一致。
断言见 `tools/loadout-tests` 的「§1.2 链式触发」段（3 把枪 × 16 条链，逐项重放后比对全量结果）。

**打断**：换枪 / 换弹 / 再扣扳机 / 死亡都会丢弃尚未触发的部分（不能留下半条链继续喷弹）。

**表现要求**：HUD 必须显示"下一发/当前发"的链，每项一个圆形配件图标；施法中已触发的点亮、
未触发的压暗、正在等待的描金边。数据源必须是真正执行的那份计划（`CastResult.Steps`），
不能 UI 另算一遍 —— 两处各算一遍迟早会漂移。

## 2. 投射物描述符（ProjectileDesc）

链解析的中间产物。一颗弹丸一个描述符。

| 字段 | 来源 | 语义 |
|------|------|------|
| `damage` | 子弹配件 | 命中伤害（爆炸弹为半径内基础伤害） |
| `ammo` | 子弹配件 | 施法时扣除的弹药点 |
| `spreadAdd` | 子弹配件 + 修正 | 散射**加法**项（度） |
| `spreadMul` | 修正 | 散射**乘法**项，初值 1.0 |
| `lifetime` | 子弹配件 + 修正 | 存在时间（秒） |
| `crit` | 子弹配件 + 修正 | 暴击率，上限 1.0 |
| `critDmg` | 子弹配件 + 修正 | 暴击倍率，初值 2.0 |
| `speedMul` | 修正 | 弹速倍率，初值 1.0 |
| `pierce` | 子弹配件 + 修正 | 可穿透敌人数 |
| `bounce` | 子弹配件 + 修正 | 撞墙反弹次数 |
| `splashRadius` | 枪/子弹 + 修正 | 命中溅射半径（米），0 = 无 |
| `homing` | 修正 | 追踪转向角速度（度/秒），0 = 无 |
| `payload` | 修正 | 命中后重放的子弹序号列表（初版留空，见 §8） |
| `sourceIndex` | 系统 | 该描述符来源的子弹配件在链中的**子弹序号**（0 起）。分裂体继承父体值 |

**有效伤害**（UI 与验收统一口径）：

```
单发期望 = damage × (1 + crit × (critDmg − 1))
整次施法期望 = Σ 所有投射物单发期望
DPS = 整次施法期望 × (1 / fireInterval) × 该位被轮到的频率
```

## 3. 结算算法（必须按此实现）

```
ResolveCast(gun, slotIndex):
  chain    ← gun.slots[slotIndex].chain            // 有序，≤6
  ctx      ← 为链中每个子弹配件生成一个 ProjectileDesc
             （携带 sourceIndex = 该子弹在链中的子弹序号）
  warnings ← []

  for item in chain:                               // 严格按链顺序
      if item is Bullet: continue                  // 本体已在 ctx 中
      if item.scope == Gun:  continue              // 枪械级在装配时已结算，见 §5.3

      targets ← SelectTargets(ctx, item)

      if targets is empty:
          warnings.push({item, code: "no-target"})  // UI 必须提示，不能静默
          continue

      for desc in targets:                          // 逐个改
          ApplyOps(desc, item)                      // 配件内部先加后乘，见 §3.2

  ammoCost ← ComputeAmmo(chain)                     // §4
  return CastResult(ctx, ammoCost, warnings)
```

### 3.1 作用域（两种子弹向 + 一种枪械向）

| 作用域 | 标记 | 目标集合 |
|--------|------|----------|
| **全场** | 蓝 | 施加时刻 `ctx` 内的**全部**描述符 |
| **后继** | 绿 | `ctx` 内 `sourceIndex > (该配件之前的子弹数量)` 的描述符 |
| **枪械** | 金 | 不作用于投射物；装配时作用于整把枪（§5.3） |

**关键推论，必须写进 UI 与新手引导**：

- **全场**配件放链里哪个位置都一样（只占链长）。它作用于「当前时刻的集合」，所以先分裂后加伤，加伤会把分裂体一起加强。
- **后继**配件只影响它**后面**的子弹。放在子弹后面 = 没有任何目标 = 白放（`no-target`）。
- 这就是「顺序即解法」的全部机制来源：**要改一颗子弹，配件必须排在它前面。**

### 3.2 配件内部运算顺序（消灭歧义）

同一个配件若同时有加法与乘法项，**固定先加法、后乘法**：

```
1) 加法项：damage += flat; crit += flat; spreadAdd += flat; lifetime += flat; pierce += n; bounce += n
2) 乘法项：damage *= mul; crit *= mul; spreadMul *= mul; lifetime *= mul; speedMul *= mul
3) 钳制：spread ≥ 0；lifetime ≥ 0.05；crit ≤ 1.0；critDmg ≥ 1.0；speedMul ∈ [0.2, 4]
```

### 3.3 逐项施法的顺序敏感性（本作核心深度，不是 bug）

| 链 | 结果 |
|----|------|
| `[校准套件 ×1.35, 增压衬片 +8, 制式弹]` | (12 × 1.35) + 8 = **24.2** |
| `[增压衬片 +8, 校准套件 ×1.35, 制式弹]` | (12 + 8) × 1.35 = **27.0** |

同一批配件换序差 11.6%。**玩家必须理解这一点**，因此：

- 配件卡面永远标注运算式（`伤害 ×1.35` / `伤害 +8`），不写「提升伤害」。
- 拖拽落点要实时显示「插在此处的生效目标数」，为 0 时落点变红。

**已实装**（`Loadout.PreviewInsert`）：返回该件的生效目标数、期望伤害变化（含百分比）、
弹药与弹丸数变化，以及拒绝码。UI 在拖拽悬停时把落点行染成 **绿（有效）／橙（无作用目标）／红（被拒）**，
并把结论写成一句话（例：`位2 插在第 1 格   生效目标 2 个   12.6 → 17.0 (+35%)`）。
对应断言 36 条，见 `tools/loadout-tests/Program.cs` 的「拖拽落点预览」段。

### 3.4 分裂与后继的交互

`量子分裂` 把 1 个描述符换成 3 个。规则：

- 子体 `sourceIndex` **继承父体**，因此排在后面的**后继**配件依然能命中子体。
- 子体属性 = 父体在分裂那一刻的**快照**（不回溯已通过的配件，也不自动吃后面的配件，除非后面的配件作用域覆盖它）。
- 分裂体**不额外消耗弹药**。弹药只由子弹配件的 `ammo` 求和。

## 4. 弹药与换弹

```
ComputeAmmo(chain):
    raw   ← Σ 链内所有子弹配件的 ammo
    raw  ← raw + Σ 弹药加法修正（如无）
    raw  ← raw × Π 弹药乘法修正（如无）
    return max(1, round(raw))        // 任何一次施法至少 1 点
```

| 规则 | 值/说明 |
|------|---------|
| 弹药池 | **无限**（初版简化：只管理弹匣，不做总弹药） |
| 扣弹时机 | 施法成功时扣 `ammoCost`；弹药不足 → 空枪提示 + 不施法 + 不前进指针 |
| 换弹 | `R` 手动或弹药不足自动；`reloadTime` 内不可开火；补满弹匣 |
| 弹匣上限变化 | 装上/卸下 `弹匣扩容` 时，当前弹药 `min(current, magSize)` |

## 5. 枪械（3 把，初版全部）

| ID | 名称 | 类型 | 位 | `damageMul` | 击发间隔 | 弹匣 | 换弹 | 基础散射 | 弹速 | 投射物基础行为 |
|----|------|------|----|-------------|----------|------|------|----------|------|----------------|
| `g_auto` | MK-2 蜂鸣 | 连发 | **3** | 1.00 | 0.11 s（≈9 发/s） | 36 | 1.8 s | 1.2° | 90 m/s | 直射、无重力 |
| `g_grenade` | HK-9 投石 | 榴弹 | **2** | 3.90 | 0.52 s | 10 | 2.2 s | 0.6° | 38 m/s | **抛射 + 重力 18 m/s²**；命中或到期爆炸，`splashRadius` = 2.8 m（子弹自带溅射则取大者） |
| `g_single` | R-71 裁决 | 单发 | **1** | 5.40 | 0.62 s | 9 | 1.9 s | 0.25° | 140 m/s | 直射、高初速、无重力 |

**枪本身不产生伤害**：没有子弹配件的链不施放。每把枪开局自带 1 个 `制式弹` 装在 1 号位。

`damageMul` 是**枪械固有伤害倍率**，作用于描述符的最终 `damage`（在链结算完成后乘，见 §5.1）。它存在的唯一理由是让「位少」的枪不吃结构性亏：

| 枪 | 位 | 每次施法可投入的链长 | 结构性劣势 | 补偿 |
|----|----|----------------------|------------|------|
| 连发 | 3 | 全部资源摊到 3 条链 | 每条链分到的配件少 | 无（靠射速与轮转多样性） |
| 榴弹 | 2 | 2 条链 | 同上，且弹匣小 | `damageMul 3.9` + 2.8m 溅射 |
| 单发 | 1 | **1 条链吃光全部配件** | 单发威力必须有足够量级 | `damageMul 5.4` |

### 5.0 实测均衡（2026-11-12 校准，蒙特卡洛命中模拟）

单体目标、20m 距离、半径 0.5m，每组 1200 次施法：

| 档位 | 连发 | 榴弹 | 单发 | 极差 |
|------|------|------|------|------|
| 裸弹 | **60.4** | 51.3 | 62.3 | 1.21× |
| 浅构筑（3 件加伤） | **121.9** | 103.5 | 125.6 | 1.21× |
| 深构筑（5 件） | **181.7** | 148.1 | 187.2 | 1.26× |

多目标（5 敌、6×3m 区域）时榴弹枪反超：

| 档位 | 连发 | 榴弹 | 单发 |
|------|------|------|------|
| 浅构筑 | 120.6 | **191.5** | 68.2 |
| 深构筑 | 183.0 | 170.0 | **274.4**（爆裂流） |

**结论**：单体差距压在 ±30% 内；群伤由榴弹枪主导、单体由单发枪主导，三者各有位置。

> 校准前的初值是 `damageMul` 连发 1.0 / 榴弹 2.6 / 单发 3.6、榴弹 0.62s/发 9 发弹匣。
> 实测发现榴弹枪在两个场景都落后 2.04–2.25 倍，据此上调榴弹 `damageMul` 至 3.9、射速至 0.52s，
> 单发至 5.4；同时把 `m_blast` 从「溅射 +1.6 / 伤害 ×1.25」降到「+1.4 / ×1.00」，
> 因为它让单发枪群伤从 68 涨到 161（2.4 倍），盖过了榴弹枪的本职。

### 5.1 枪械基础属性如何并入描述符

| 枪字段 | 并入方式 |
|--------|----------|
| `spreadBase` | `desc.spreadAdd += spreadBase`（在链结算**之前**并入，因此会被 `稳定器` 的乘法一并作用） |
| `muzzleSpeed` | `desc.speed = muzzleSpeed × speedMul` |
| `damageMul` | 链结算**全部完成后**，`desc.damage *= damageMul`（这样配件之间的加法先后不受枪影响，便于算例复现） |
| 榴弹的 `splashRadius` | `desc.splashRadius = max(枪基础, 子弹自带)` |
| 榴弹的抛射/重力 | 描述符不记录，由枪的 `projectileMode` 决定（`Straight` / `Ballistic`） |

**注意 `damageMul` 在链结算之后生效**：§9 全部算例基于 `g_auto`（`damageMul = 1.0`），所以算例数字可直接当断言值。其它枪的算例另行给出。

### 5.2 榴弹的爆炸结算

爆炸伤害 = `damage`，半径 `splashRadius` 内所有敌人按线性衰减承受：

```
实际伤害 = damage × lerp(1.0, 0.45, 距离 / 半径)
```

对自伤：**不伤玩家**（初版取消友伤，避免玩家被自己的构筑炸死）。

### 5.3 枪械级配件结算时机

`枪械` 作用域的配件放在链里任意位置都生效，作用于**整把枪**：

| 规则 | 说明 |
|------|------|
| 结算时机 | 装配/卸下/换枪时重算一次，**不在施法时**算 |
| 叠加 | 同名配件在同一把枪上**只生效 1 个**（多个只取第一个） |
| 位置无关 | 放在哪个位、链中哪一格都不影响 |
| 重算后钳制 | `magSize ≥ 1`、`fireInterval ≥ 0.05`、`globalSpreadMul ∈ [0.2, 2]` |

|----|------|------|------|------|----------|--------|----------|------|--------|
| `b_slug` | 制式弹 | 12 | 2 | +0° | 1.2 s | 5% | 2.0 | 无。每把枪的起手件 | 起始 |
| `b_heavy` | 重芯弹 | 26 | 3 | +1.5° | 1.0 s | 8% | 2.0 | 无 | 常见 |
| `b_pellet` | 霰粒 | 6 | 1 | +3.0° | 0.6 s | 3% | 1.5 | 无。适合多个叠放 | 常见 |
| `b_pierce` | 穿甲钉 | 15 | 2 | +0° | 1.6 s | 10% | 2.2 | 自带穿透 2 个敌人 | 稀有 |
| `b_ricochet` | 跳弹 | 9 | 2 | +0.5° | 1.8 s | 6% | 2.0 | 撞墙反弹 2 次（不衰减） | 常见 |
| `b_plasma` | 电浆团 | 18 | 3 | +0.2° | 1.4 s | 7% | 2.5 | 命中溅射 1.2 m | 稀有 |
| `b_incend` | 燃素弹 | 10 | 2 | +0.3° | 1.1 s | 5% | 2.0 | 命中附着燃烧：8 dmg/s × 3 s（可叠加 3 层） | 常见 |

| `b_null` | 空蚀弹 | 4 | 1 | +0° | 0.9 s | 4% | 1.8 | **无视护甲**（盾卫正面减伤也穿透一半） | 稀有 |
| `b_lance` | 光矛 | 34 | 5 | +0° | 0.7 s | 12% | 2.8 | 弹速 ×1.6 | 史诗 |

**为什么制式弹是弹药 2**：连发枪弹匣 36 → 单发 18 次击发 = 2 秒连射。弹药是「你能连打多久」的直接预算，比伤害更能约束构筑。

**霰粒的设计意图**：弹药 1、伤害 6、散射大。单看很弱，但叠到同名上限（2 个）就是弹药 2、总伤 12、散射 +6°；配合分裂（`量子分裂` 把它变成 3 发）就是近距离的弹幕喷子。它是「位置与世界决定价值」的教学件——同一个件在不同链里强弱差三倍。

## 7. 衍生配件（15 种）

### 7.1 数值向（8 种）

| ID | 名称 | 作用域 | 效果（原文即运算式） | 稀有度 |
|----|------|--------|----------------------|--------|
| `m_dmg_up` | 校准套件 | 全场 | 伤害 **×1.35** | 常见 |
| `m_dmg_flat` | 增压衬片 | 后继 | 伤害 **+8** | 常见 |
| `m_crit_up` | 激光准星 | 全场 | 暴击率 **+12%** | 常见 |
| `m_critdmg` | 中空改造 | 全场 | 暴击倍率 **+0.6** | 稀有 |
| `m_spread_down` | 稳定器 | 全场 | 散射 **×0.60** | 常见 |
| `m_life_up` | 延时引信 | 全场 | 存在时间 **+0.5 s** | 常见 |
| `m_ammo_down` | 弹链优化 | 全场 | 弹药消耗 **−1**（施法最低 1） | 稀有 |
| `m_speed_up` | 加速器 | 全场 | 弹速 **×1.60**，伤害 **×0.85** | 稀有 |

### 7.2 行为向（4 种）

| ID | 名称 | 作用域 | 效果 | 稀有度 |
|----|------|--------|------|--------|
| `m_split` | 量子分裂 | 后继 | 每个目标投射物**分裂为 3 个**：伤害 **×0.55**、散射 **+2°**、存在时间 **×0.8** | 稀有 |
| `m_pierce` | 穿透射击 | 全场 | 穿透 **+2**，伤害 **×0.85** | 稀有 |
| `m_homing` | 制导 | 全场 | 追踪（转向 180°/s），伤害 **×0.90** | 稀有 |
| `m_blast` | 爆裂装药 | 全场 | 溅射半径 **+1.4 m**，伤害不变 | 史诗 |

**为什么 `m_blast` 是史诗**：溅射让「打不中也能打伤」，是 FPS 里最强的容错属性。它把单体链变成群体清场链，是构筑分叉的关键件。

**校准记录（2026-11-12）**：初版是「溅射 +1.6 / 伤害 ×1.25」，实测发现它让单发枪群伤从 68 涨到 161（2.4 倍），
超过榴弹枪的本职（170）。降为「+1.4 / ×1.00」后，单发枪群伤 121.8，榴弹枪 170，层级恢复。

> 原设计的 `延时载荷`（命中后重放另一颗子弹）涉及跨配件引用与递归，语义与实现成本都远超初版需要，**已移出初版**。见 §10。

`m_trigger` 是唯一「引用其他配件」的修正，实现成本最高，排在拆解 P2；未实装时该件不出现在掉落池。

## 8. 背包与拖拽规则

| 项 | 规则 |
|----|------|
| 背包容量 | **24**（配件计数，子弹与衍生都算 1） |
| 打开方式 | `Tab`，**打开即暂停**游戏；关闭时若有非法链会高亮但**不阻止**关闭 |
| 拖入 | 从背包拖到某位的链上任意位置 → 插入该位置 |
| 拖出 | 从链拖回背包 → 卸下；拖到空地 → 丢弃（需二次确认） |
| 链长上限 | 每位 **6** 项（含子弹与衍生） |
| 同名上限 | **同一条链**内同名配件最多 **2** 个 |
| 枪械级同名 | 同一把枪上同名枪械配件只生效 1 个（可放多个，多余的无效果并标灰） |
| 空链 | 允许，标记为空，轮转跳过 |
| 无目标警告 | 链内存在 `no-target` 的衍生配件 → 该件描边变红 + 位标题显示 ⚠ |
| 换枪 | 背包里可切换 2 把枪；**配件不随枪走**，换枪后各自链保持原状 |
| 升级顶替 | 背包满时抽到新配件 → 必须当场选一个丢弃或放弃新件 |

**拖拽是本作唯一的「操作技能」**：没有 QTE、没有闪避判定，深度全在背包里。因此拖拽手感是 P0 验收项（见 `breakdown/`）。

## 10. 已知边界（明确不做 / 暂不做）

| 项 | 决定 |
|----|------|
| 触发/定时嵌套 | 初版只允许**一层**载荷（`m_trigger` 重放的子弹不再触发载荷），防止无限递归 |
| 永久化投射物 | 不支持（`lifetime` 钳制下限 0.05，无「无限」词条） |
| 友伤 | 取消 |
| 配件改外观 | 取消，纯数值与行为 |
| 链内嵌套链 | 不支持（无「施法块」概念，一条位一条链） |
| 配件升级/合成 | 取消（初版只做掉落与拾取） |
