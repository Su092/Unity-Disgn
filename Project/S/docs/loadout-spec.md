# 配件规则与数值 — S（对齐 MODCORE 原型）

> 本文是 `unity/Assets/Resources/Data/sdata.json` 的人读镜像，也是配件的**唯一权威**。
> 环境与成长见 `gameplay-spec.md`；字段契约见 `data-schema.md`。
>
> 2026-11-15 重写：链模型从「时间序列」换成**读取式扫描**（对齐 `modcore-prototype`）。
> 旧版「一条链按顺序逐项触发、衍生件在前或在后」的规则**已作废**。

## 1. 一句话

枪是**容器**，配件是**内容**。一次射击是「从指针位置顺时针扫格子，读到什么就打什么」。

## 2. 作用域（7 种，本作的核心机制）

| 作用域 | 中文 | 是否占读取 | 作用对象 | 耗弹倍率 |
|--------|------|------------|----------|----------|
| `Next` | 下一发 | **是** | 之后读到的**第一个**子弹 | ×1 |
| `Prev` | 上一个 | 否 | 左侧最近的**一个子弹** | ×1 |
| `Adj` | 相邻 | 否 | 左右各一格内的子弹 | ×0.8 |
| `N2` | 后 2 格 | 否 | 右侧 2 格内 | ×0.75 |
| `N3` | 后 3 格 | 否 | 右侧 3 格内 | ×0.6 |
| `P2` | 前 2 格 | 否 | 左侧 2 格内 | ×0.75 |
| `All` | 全枪 | 否 | 整把枪（枪属性或全部子弹） | ×0.4 |

**为什么扩到 7 种**：原版只有「全场 / 仅后方」两档，作用域是个开关。
七档作用域让「把同一张伤害增幅放哪」变成真决策——放 `Next` 会占一次读取（少打一发别的），
放 `Prev` 免费但只能影响左边一颗，放 `All` 影响全部但要占用一个昂贵槽位。

**`Prev` 的精确定义**：向左找最近的**子弹**，跳过中间所有衍生件。
这条是实现里最容易写错的地方——写成「左一格」会让玩家无法通过中间塞件来精确控制影响对象。

## 3. 结算流程

```
扣扳机
  │
  ├─ 从 Cursor 起顺时针扫格子
  │    ├─ 空格      → 跳过
  │    ├─ Next 件   → 记录（占一次读取），继续扫
  │    ├─ 被动件    → 跳过（不占读取）
  │    └─ 子弹      → 产出一次射击，读够 castCount 发就停
  │
  ├─ 每发子弹的最终属性 =
  │      自身基础值
  │    × 枪械倍率（DmgMul / SpreadMul）
  │    + 吸附到它的所有被动件（按层数叠加）
  │    + 前置的 Next 件
  │
  ├─ 触发弹 → 递归解析 1 个载荷（跟子弹走，最多 6 代）
  │
  ├─ 扣弹 = Σ(读到格子的 cost) + Σ(吸附的被动件 cost)
  ├─ 射击间隔 = (枪基础 delay + 读到件的 delay 之和) × 枪械 delayMul
  └─ 指针 → 落到最后一次读取之后
```

### 3.1 叠加层数（t）

同一件配件在一次结算里可能出现多次（例如 `Prev` 和 `N2` 都覆盖到同一颗子弹），
效果按 **t 次**叠加：

| 类型 | 公式 |
|------|------|
| 乘法项 | `值 × (1 + add × t)` |
| 加法项（穿透/反弹） | `+ max(1, round(per × t))` |
| 减速 | `max(当前, per × min(1, t + 0.2))` |

### 3.2 爆裂的特殊规则

| 情况 | 结果 |
|------|------|
| 子弹本身无爆裂 | 半径 = `explodeRBase`（2.5 m） |
| 子弹本身有爆裂 | 半径 `× (1 + 0.25 × t)` |
| 爆炸伤害 | `+(伤害 × 0.8 + 12) × t` |

**为什么区分两种**：榴弹本来就爆，再挂爆裂应该「更大」而不是「变成 2.5m」——
后者会让玩家觉得这个配件是负面效果。

### 3.3 触发弹

| 触发条件 | 时机 |
|----------|------|
| `Hit` | 首次命中敌人或表面 |
| `Timer` | 飞行 0.4 s 后 |
| `Expire` | 穿透/反弹耗尽、生命结束 |

载荷是「下一个子弹（连同吸附它的被动件）」，递归上限 **6 代**。
只触发一次——穿透弹连打三个敌人时载荷不应重复施放（否则指数爆炸）。

### 3.4 弹药

```
耗弹 = Σ(被读取格子的 cost) + Σ(吸附到这些子弹的被动件 cost)
```

- 子弹 `cost` 1–6，被动件 `cost` 0–2，`节能回路` 是 **−1**（可把子弹压到 0 弹）。
- 总耗弹下限 0，上限 = 弹匣容量。
- 弹匣打空自动换弹；换弹**不重置指针**。

### 3.5 施法序列（HUD 用）

`Loadout.FullSequence` 从格 0 起反复解析，直到绕回起点。
HUD 用 `ResolveCast` 预览「下一发会打出什么」，与实战**同一个函数**，所以数字不可能不一致。

## 4. 枪械（6 把）

| ID | 名称 | 槽位 | 弹匣 | 换弹 | 击发 | 散射 | 读取 | 基础弹 |
|----|------|------|------|------|------|------|------|--------|
| `rifle` | 制式步枪 | 8 | 30 | 1.5 s | 0.14 s | 1.2° | 1 | 标准弹 |
| `smg` | 冲锋枪 | 10 | 50 | 1.7 s | 0.075 s | 3.5° | 1 | 轻型弹 |
| `shotgun` | 战术霰弹枪 | 6 | 10 | 1.9 s | 0.6 s | 2.0° | **2** | 霰弹 |
| `sniper` | 精确射手步枪 | 6 | 9 | 2.2 s | 0.85 s | **0°** | 1 | 穿甲弹 |
| `beam` | 光束发射器 | 8 | 80 | 2.0 s | 0.06 s | 0.6° | 1 | 激光束 |
| `launcher` | 多功能发射器 | 12 | 14 | 2.4 s | 0.7 s | 1.0° | 1 | 榴弹 |

**设计意图**：
- `shotgun` 读 2 发 → 天生适合「两个不同子弹交替」
- `launcher` 12 槽 → 天生适合「复杂连锁 + 多个触发弹」
- `sniper` 零散射 + 单发高伤 → 天生适合「堆乘法」
- `smg` 10 槽 + 极快射速 → 天生适合「挂低耗被动件铺满」

## 8. 装配交互（对齐原型 #inventory）

| 操作 | 结果 |
|------|------|
| 拖拽件到槽位 | 装入；槽位已有件则**交换**（不覆盖，避免误丢） |
| 右键件 | 快速装 / 卸 |
| 拖到空白 | 从槽位卸回背包 |
| 鼠标悬停在配件上 | 详情区显示完整内容（名称/稀有度/作用域/数值/用法） |
| 拖拽到槽位上方 | 详情区切到**落点预览**：本次期望 前 → 后（增减）、耗弹变化、生效目标数 |
| 落点没有目标 | 提示「没有作用目标，效果会全部落空」（红字） |

**为什么落点预览要真跑一次结算**：读取式链的产出取决于扫描顺序与作用域吸附，
纸面加法算不出来。这里在槽位副本上跑 `ResolveGun` + `ResolveCast`，
拿到的是**真实**的前后对比，不是估算。

**为什么详情常驻在背包里**：浮动提示会挡住相邻格子，玩家想对比两件时没法同时看见。
HUD 链条与三选一卡片没有常驻区域，仍用浮动提示 —— 两者的数值文案同源于
`ItemTooltip` 的静态方法，不会各写一套而漂移。

**为什么交换而不是覆盖**：配件是唯一资源，覆盖等于无声销毁玩家刚拿到的东西。
代价是最多做两次拖拽，收益是永不误丢。

## 10. 与旧规则的差异（一次性记录，实现时不要回退）

| 项 | 旧 | 新 |
|----|----|----|
| 一格内容 | 一条可叠多件的「链」 | **一件** |
| 触发方式 | 按链顺序在时间轴上逐项触发 | **一次性扫描解析出全部投射物** |
| 作用域 | 全场 / 后继 / 枪械（3 种） | **7 种** |
| 步枪 shot | 固定 1 发 | `castCount` 决定 |
| 伤害公式 | 链上加法与乘法分层结算 | 逐件 `apply(desc, t)` 就地改写 |

**为什么要推翻**：旧模型的表现力上限是「一条链能塞几件」，
新模型的上限是「20 种子弹 × 22 种件 × 7 种作用域 × 6 把枪」。
后者才是「顺序即解法」这句话真正站得住的规模。
