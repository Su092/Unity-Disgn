# 跨终端部署手册

在**新机器**上从零把本工作区跑起来。按本文件顺序执行即可，不需要看聊天记录、不需要参考另一台机器的现状。

读完你会得到：三个游戏工程各自可打开、`doctor.ps1` 输出 `pass`、Unity 与 Blender 工具链可用。

---

## 0. 先理解三层结构

| 层 | 位置 | 是否入库 |
|----|------|----------|
| L1 枢纽 | `<HUB>`（本仓库） | 是 |
| L2 游戏工程 | `<GAME:id>`（各自独立仓库） | 各自仓库 |
| L3 机器绑定 | `machine/profile.local.json` | **否** |

**跨终端的一切差异都在 L3。** 换机时唯一需要新填的文件是 `machine/profile.local.json`，其余全部从仓库来。

本手册用记号书写，落地时按你的实际盘符替换：

| 记号 | 含义 |
|------|------|
| `<HUB>` | 枢纽仓库根（你克隆到的位置） |
| `<GAME:id>` | 某游戏真实工程根 |
| `<UNITY:6000.6.4f1>` | 指定版本编辑器可执行文件 |
| `<BLENDER>` | Blender 可执行文件 |

## 1. 前置依赖

| 依赖 | 最低 | 检查命令 | 缺失后果 |
|------|------|----------|----------|
| Windows + PowerShell | 5.1 | `$PSVersionTable.PSVersion` | 脚本全部不可用 |
| Git | 2.30+ | `git --version` | 无法拉取 |
| Unity Hub + Unity 6000.6.4f1 | 6000.6.4f1 | 见 §1.1 | 工程打不开 |
| Git SSH 密钥 | 已加到 GitHub | `ssh -T git@github.com` | 无法克隆私有仓库 |
| Blender 5.2 | 5.2 | 见 §1.2 | 3D 管线不可用（其余可开发） |
| uv / uvx | 任意 | `uvx --version` | blender MCP 不可用 |
| .NET SDK 8 | 8.0 | `dotnet --list-sdks` | 仅 S 的 `-Task tests` 不可用 |

**PowerShell 必须是 5.1 或更新。** 本仓库的 `.ps1` 含中文且全部为 UTF-8 with BOM；若你用其它工具重新保存过脚本，务必保留 BOM。

### 1.1 Unity 编辑器

Unity Hub 里安装 **6000.6.4f1**。三款游戏共用同一版本，装在哪个盘由你决定，只要在 `profile.local.json` 的 `tools.unityEditorRoot` 指对。

`unityEditorRoot` 的语义是「其下按版本号分子目录」，因此完整路径应为：

```text
<unityEditorRoot>\6000.6.4f1\Editor\Unity.exe
```

验证：

```powershell
Test-Path "<unityEditorRoot>\6000.6.4f1\Editor\Unity.exe"   # 必须 True
```

**不要**用 2022.3 或团结引擎打开这些工程。`Star Defanse` 是内置管线，**不要给它装 URP**。

### 1.2 Blender

Steam 版或官网版均可，需 **5.2**（`blender-asset-pipeline` 技能在 5.2 校准）。记下 `blender.exe` 绝对路径，填进 `tools.blender`。

`blender-gate.ps1` 的路径优先级：`profile.tools.blender` → `$env:BLENDER_EXE` → 默认安装目录 → `PATH` 里的 `blender`。

## 2. 克隆

三个仓库相互独立，**必须并列克隆，不要嵌套**。

```powershell
# 选一个位置，例如 F:\
cd F:\

git clone git@github.com:Su092/Unity-Disgn.git      "F:\Unity Development"
git clone git@github.com:Su092/Kingdom-Of-Cloud.git "F:\Kingdom Of Cloud"
git clone git@github.com:Su092/Star-Defanse.git     "F:\Star Defanse"
git clone git@github.com:Su092/Project-S.git        "F:\S"
```

拿到路径后记下来，下一步要填进 profile。

> **不要**把游戏工程克隆到 `<HUB>\Project\` 里面。那会形成嵌套 Git 并让 `Library` 进枢纽仓库。
> 游戏工程通过 `unity` 目录联接挂到枢纽，由 `bootstrap.ps1` 建立。

## 3. 生成 profile.local.json

```powershell
cd "F:\Unity Development"
Copy-Item machine\profile.example.json machine\profile.local.json
notepad machine\profile.local.json
```

按下表逐项填写。**`games` 的键必须与 `<HUB>\Project\` 下的目录名逐字一致（含空格）**，因为联接路径是按它拼的。

| 字段 | 填什么 | 示例 |
|------|--------|------|
| `machine` | 机器代号，仅给人看 | `"B"` |
| `hub.real` | 枢纽真实根 | `"F:\\Unity Development"` |
| `hub.link` | 可选：给枢纽建个联接方便访问；不需要就填 `""` | `"E:\\Unity Development"` |
| `tools.unityEditorRoot` | 编辑器版本的上级目录 | `"F:\\Unity Hub\\Unity"` |
| `tools.blender` | blender.exe 绝对路径 | `"E:\\Steam\\steamapps\\common\\Blender\\blender.exe"` |
| `tools.uvx` | uvx.exe 绝对路径（`where.exe uvx` 可查） | `"C:\\Users\\<你>\\.local\\bin\\uvx.exe"` |
| `mcp.blenderHost` | 一般不改 | `"127.0.0.1"` |
| `mcp.blenderPort` | 一般不改 | `9876` |
| `mcp.unityBridgeUrl` | 一般不改 | `"http://127.0.0.1:8765/mcp"` |
| `games."Kingdom Of Cloud".path` | 该工程克隆到哪 | `"F:\\Kingdom Of Cloud"` |
| `games."Star Defanse".path` | 同上 | `"F:\\Star Defanse"` |
| `games."S".path` | 同上 | `"F:\\S"` |

三个 `games.*.remote` 与 `games.*.editor` 已写好，一般不用改。

**JSON 注意事项**：Windows 路径里的反斜杠必须写成 `\\`；不要加注释（`profile.local.json` 是严格 JSON）。

填完先自检语法：

```powershell
Get-Content machine\profile.local.json -Raw -Encoding UTF8 | ConvertFrom-Json | Out-Null
# 无输出即合法；报错说明逗号/引号/反斜杠有问题
```

`profile.local.json` 已被 `.gitignore` 忽略，不会误提交。

## 4. 装配

```powershell
powershell -ExecutionPolicy Bypass -File "F:\Unity Development\machine\bootstrap.ps1"
```

它做四件事，**幂等**，可反复运行：

1. 建枢纽联接（若 `hub.link` 非空）。已存在且指向正确 → 跳过；指向错误 → 报告（加 `-Force` 才重建）
2. 为每个游戏建 `<HUB>\Project\<id>\unity` → `<GAME:id>` 联接
3. 按 profile 生成 `.cursor/mcp.json` 与 `.codex/config.toml`
4. 检查凭据与工具（`tools/.apimart.key`、Blender、uvx、Unity）

只处理一个游戏：

```powershell
powershell -ExecutionPolicy Bypass -File "F:\Unity Development\machine\bootstrap.ps1" -OnlyGame S
```

期望看到每行都是 `[ok]` 或 `[new]`，末尾 `警告 0 项`，退出码 0。

**`bootstrap.ps1` 不做的事**（需要你手工）：克隆仓库、安装 Unity / Blender / uv、创建 `profile.local.json`、拷贝凭据。

---

## 5. 凭据

`tools/.apimart.key` 不入库（已 gitignore）。从另一台机器拷贝，或重新申请。

```powershell
# 从旧机器拷（在旧机器上执行，或直接复制文件）
# 目标：<HUB>\tools\.apimart.key
Test-Path "<HUB>\tools\.apimart.key"
```

缺失只影响 APIMart 生图（`apimart-image` 技能），不影响编译、验证与 3D 管线。`doctor.ps1` 会把它记为 `degraded` 而非 `fail`。

## 6. 验收

```powershell
powershell -ExecutionPolicy Bypass -File "F:\Unity Development\machine\doctor.ps1"
```

八项检查：profile、枢纽与联接、每个游戏（路径/版本/远端/联接）、工具、凭据、MCP 一致性、技能单源、脚本编码。

**判据：输出 `RESULT: pass`，退出码 0。**

| 结果 | 退出码 | 含义 | 动作 |
|------|--------|------|------|
| `pass` | 0 | 全部通过 | 可以开发 |
| `degraded` | 2 | 无硬错误但有缺口（如缺 .NET SDK、缺凭据、某游戏未克隆） | **必须逐条补查，不许当通过** |
| `fail` | 1 | 有硬错误（路径错、联接错、MCP 不一致、缺 profile） | 按输出逐条修，修完重跑 |

常见 `fail` 与处置：

| 输出 | 原因 | 处置 |
|------|------|------|
| `枢纽联接悬空或指错` | 旧机器的联接残留，或指向已改名目录 | `bootstrap.ps1 -Force` |
| `unity 联接缺失` | 没跑过 bootstrap | `bootstrap.ps1` |
| `工程版本 X ≠ profile.editor Y` | profile 填错或工程克隆错分支 | 改 profile 或换分支 |
| `远端 A ≠ profile B` | 克隆的不是预期仓库 | 重新克隆正确仓库 |
| `MCP 配置与 profile 不一致` | 手改过 MCP，或 bootstrap 没跑 | 重跑 `bootstrap.ps1`（不要手工改） |
| `含中文但无 BOM 的 .ps1` | 用其它编辑器重存过脚本 | 见 §10 |

静默模式与单游戏：

```powershell
powershell -ExecutionPolicy Bypass -File "F:\Unity Development\machine\doctor.ps1" -Quiet
powershell -ExecutionPolicy Bypass -File "F:\Unity Development\machine\doctor.ps1" -OnlyGame S
```

## 7. 各游戏验证入口

`doctor.ps1` 全绿只代表**绑定正确**，不代表工程能构建。逐游戏跑一次验证：

```powershell
# Star Defanse
powershell -ExecutionPolicy Bypass -File "<HUB>\Project\Star Defanse\unity\scripts\check.ps1" -Task all

# S
powershell -ExecutionPolicy Bypass -File "<HUB>\Project\S\unity\scripts\check.ps1" -Task all
```

判据：输出含 `RESULT` 且无 `FAIL`，退出码 0。

**跑 Unity 相关任务前必须先关掉编辑器**（工程锁会让 batchmode 启动即退出或长时间干等）。S 的 `check.ps1` 在 shots 前会自动清理残留进程。

### 7.1 已知换机坑（按本手册部署后仍可能遇到）

| 现象 | 原因 | 处置 |
|------|------|------|
| `check.ps1` 报「找不到 Unity 编辑器」 | 该脚本从 profile 取路径，三级查找（`$env:UNITY_EXE` → `$env:HUB_ROOT` → 与工程同级的 `Unity Development`）全部失败 | 先确保 `machine/profile.local.json` 的 `tools.unityEditorRoot` 正确；工程不在枢纽同级目录时，开工前设一次 `$env:HUB_ROOT = "<HUB>"` |
| S 的 `-Task tests` 直接失败 | 本机无 .NET SDK，且 `tools/loadout-tests/*.csproj` 被工程 `.gitignore` 忽略、不随仓库分发 | 装 .NET 8 SDK，再按 `<GAME:S>\tools\loadout-tests\` 下的源码重建 `.csproj`；其余任务（setup/assets/ui/build/smoke/shots）不受影响 |
| 打开工程提示版本不符 | 只装了别的 Unity 版本 | 装 6000.6.4f1 |
| `<HUB>` 内文件在别的盘符访问不到 | `hub.link` 没配或联接指错 | 在 profile 里填 `hub.link`，跑 `bootstrap.ps1 -Force` |
| `mklink` 报「权限不足」 | 未以管理员运行 | 目录联接（`/J`）通常无需提权；若被策略限制，以管理员开一次 PowerShell 再跑 `bootstrap.ps1` |

Kingdom Of Cloud **没有** `scripts/check.ps1`，验证方式以该游戏 `PROJECT.md` 为准。

## 8. MCP 桥（需要时再配）

MCP 配置已由 `bootstrap.ps1` 生成，但**桥本身要手工启动**：

| 场景 | 前置 |
|------|------|
| Unity MCP | 打开目标工程，且该工程装了 `com.coplaydev.unity-mcp`；S **尚未装** |
| Blender MCP | 打开 Blender，启用对应插件并监听 `9876` |

桥没起来时，Cursor / Codex 里对应工具为空，这不影响代码与文档工作。**不要手工编辑** `.cursor/mcp.json` 或 `.codex/config.toml`——改 profile 后重跑 `bootstrap.ps1`。

## 8.1 `_Inbox` 与资产分层（每个工程都要有）

工程根的 `_Inbox/` 放**未处理的原料**，`Assets/` 只放**能直接进引擎的交付件**：

| 类别 | 位置 | 入库 |
|------|------|------|
| 交付件 | `<GAME:id>/Assets/` | 是 |
| **原料**（AI 原图 / 参考图 / 预览渲染 / 中间态） | `<GAME:id>/_Inbox/` | **是** |
| 运行产物（截图 / 模型对照图） | `<GAME:id>/Shots/` 等 | 否（gitignore，可重生成） |
| 结论（规格、数值、口径） | `<HUB>/Project/<Game>/docs/` | 是（纯文字） |

`_Inbox/` **入库**，所以换机 `git pull` 后原料直接可用，不需要重新生图。S 的 `_Inbox` 约 71 MB，
最大单文件 7.6 MB，远低于 GitHub 100 MB 硬限，用普通 git 即可。

- 只有**运行产物**（如 S 的 `Shots/`、Star 的 `_Inbox/terrain` 中间图）才 gitignore。
- 枢纽 `docs/` **只放 markdown**，不要提交图片副本或 `.docx`——原图归 `_Inbox/`。
- 新建游戏时建 `_Inbox/` 并放一份 `README.md` 说明（照抄任一现有工程的即可）。
- 若日后单仓库超过约 500 MB，再对该工程启用 LFS；现在不需要。

## 9. 日常跨终端时序

单人多机的冲突只在「两台机器同时改同一处」时发生。约定：

```text
开工：git pull（枢纽 + 今天要动的那个游戏仓库）
      doctor.ps1  →  pass 才动手

收工：先提交文档/记忆，再提交代码
      推枢纽仓库与游戏仓库（两个独立仓库，分开 push）
```

- **动手前先 pull，收工必 push**，不留跨机器的未提交改动。
- 一次只在一台机器上动同一个游戏。切机器前确认该仓库工作区干净（`git status` 无输出）。
- 记忆文件 `memory/CURRENT.md` 是「当前快照」语义（整文件覆盖），不同时在两台机器编辑它。
- 3D 交付件（`.blend` / `.fbx`）走各自仓库；`Blender Modle/**/refs/*.png` 与 `renders/` 已 gitignore（可重生成）。

## 10. 维护纪律

- **不要在文档或脚本里写裸盘符。** 用 `<HUB>` / `<GAME:id>` / `<UNITY:ver>` / `<BLENDER>`；绝对路径只允许出现在 `machine/profile.local.json`。
- **不要手工编辑 MCP 配置**，它由 `bootstrap.ps1` 生成；`doctor.ps1` 会校验不一致。
- **手改 `.ps1` 后确认 UTF-8 with BOM**：

  ```powershell
  $p = "<路径>"
  $t = [IO.File]::ReadAllText($p)
  [IO.File]::WriteAllText($p, $t, [Text.UTF8Encoding]::new($true))
  ```

  无 BOM 时 PowerShell 5.1 按 GBK 解码，中文会把引号配对搞乱，报 `Unexpected token ')'` 且行号指向无关位置。`doctor.ps1` 第 8 项会检查。
- **技能单一源头**：`.cursor/skills/`。`.codex/skills/blender-asset-pipeline/` 是 Codex 宿主的派生改写版（带 `ADAPTATION.md`），内容有意不同，**不要同步**。不要再建 `.agents/skills/` 或根级副本；第 7 项会检查越界 `SKILL.md`。
- 新增游戏：改 `profile.local.json` 的 `games` → 建 `<HUB>\Project\<id>\` 目录与 `PROJECT.md` → 跑 `bootstrap.ps1 -OnlyGame "<id>"` → 跑 `doctor.ps1`。详见 `<HUB>\Project\README.md`。

## 11. 部署完成判据

以下四条全部成立才算部署完成：

1. `doctor.ps1` 输出 `RESULT: pass`（退出码 0）
2. 至少一个游戏的 `check.ps1` 跑出 `RESULT ALL PASS`
3. `<HUB>\Project\<id>\unity` 联接能打开真实工程的 `Assets` 目录
4. `git status` 在枢纽与各游戏仓库都无意外改动（`machine/profile.local.json` 不会出现在未跟踪列表里）

未达成的项，按 §6 的处置表逐条修。**`degraded` 不算完成**——它是「没查完」。
