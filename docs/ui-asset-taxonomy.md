# UI 素材分类规范（跨项目通用）

> 适用：`<HUB>/Project/*/` 下所有 Unity 游戏。
> 单一权威；项目 `docs/` 只写该项目**具体素材落在哪一类**，不重写分类定义。

## 1. 为什么要分类

UI 素材平铺在一个目录里，到 60~70 张就会出三类问题，而且都是**静默**的：

| 问题 | 表现 |
|------|------|
| 找不到 | 想换「面板底」得先知道它叫 `panel` 还是 `plate_dark`；名字不带功能信息 |
| 改不动 | 换肤要动整体观感时，分不清哪些是「一处专属」、哪些是「处处都在用」 |
| 数不准 | 「配件图标齐了吗」需要人肉比对，漏一张只会表现为某个格子空着 |

分类不是为了整齐，是为了让上面三件事变成**可判定**的。

## 2. 判据：按「服务几个地方」，不是按「长什么样」

这是本规范唯一需要记住的原则。同一张圆角暗色图，可能是三种完全不同的东西：

- 到处都在用的面板底 → **Common**
- 只包住内容的卡片框（要 9-slice 拉伸）→ **Frame**
- 有悬停态的按钮 → **Widget**

按外观分会把这三者塞进同一个「面板类」，然后换肤时无法判断影响范围。

## 3. 六个分类

| 分类 | 判据 | 典型素材 | 换掉它的影响 |
|------|------|----------|--------------|
| `Common` | 出现 ≥3 处，或跨界面 | 面板底、横幅、全屏晕影、分隔线 | **全局换肤** |
| `Frame` | 包裹内容，9-slice 拉伸，带 border | 卡片框、卡内衬、条外框 | 所有卡片/条目外观 |
| `Widget` | **有状态**（正常/悬停/危险、空/满）或承载实时数值 | 按钮、槽位、进度条、准星、命中标记、键帽 | 交互手感与可读性 |
| `Tag` | 表达一个**离散状态**，颜色本身就是信息 | 稀有度标签条 | 信息编码 |
| `Icon` | 静态语义符号，无状态、不承载数值 | 作用域图标、锁/勾/箭头 | 语义可读性 |
| `Icon/Items` | **数据驱动**，按数据 id 动态取图 | 配件图标 `item_<id>` | 配件识别 |

### 为什么 `Icon/Items` 要单独一层

它是唯一「文件与数据行一一对应」的分类：数据里加一件配件，就必须加一张图，删一件就得删一张图。这条流程只对这**一个**目录成立，混在 `Icon/` 里会让这条约束失效。

同时它让校验变简单：`Items` 下的文件名集合，去前缀后必须与数据 id 集合**完全相等**（不多不少）。

### 边界裁定

拿不准时按这个顺序问：

1. **它的数量由数据决定吗？** → 是则 `Icon/Items`
2. **它表达的是「某个离散状态」吗？** → 是则 `Tag`
3. **它自身有状态，或用内边距承受拉伸？** → 是则 `Widget`
4. **它只包住内容、本体不需要随尺寸变形吗？** → 是则 `Frame`
5. **它被 ≥3 处共用，或换掉它等于整体换肤吗？** → 是则 `Common`
6. **剩下的是纯符号** → `Icon`

> 反例：`divider` 长得像 `Frame`（细长条），但它出现在背包/菜单/结算多处且没有内边距语义 → `Common`。
> 反例：`slot_empty` / `slot_filled` 看着像 `Frame`，但它们表达「空/占用」这个状态 → `Widget`。

## 4. 目录布局

```
<GAME>/Assets/Resources/UI/
  mat_ui_additive.mat        ← 材质，不是 sprite，留根目录
  Prefabs/                   ← 预制体，不动
  Sprites/
    Common/
    Frame/
    Widget/
    Tag/
    Icon/
      Items/                 ← 配件图标（数据驱动）
```

**根目录规则**：`Resources/UI/` 根下**只允许**放材质、Prefabs 这类非 sprite 资产。任何 `.png` 都必须落在 `Sprites/<Category>/` 里。校验脚本会把根目录残留的 png 直接判红。

## 5. 实现纪律（三条，都是踩出来的）

### 5.1 素材名 → 分类只允许有一处真相

分类表会同时被运行时与工具链需要，天然存在多份。**必须集中**，禁止在加载处、预制体工厂、校验脚本里各写一份路径拼接。

各项目的落法：

| 项目 | 唯一真相位置 |
|------|--------------|
| S | `Assets/_Game/View/UiAssets.cs` 的 `Catalog`（运行时与编辑器都查它） |

工具链（Python）**无法**读 C#，所以只能有第二份拷贝 —— 用校验脚本比对，不靠人记。见 §6。

### 5.2 移动素材必须连 `.meta` 一起移动

Unity 用 `.meta` 里的 GUID 维持引用。只移动 `.png` 会让 GUID 重新生成，结果是：

- 预制体 / 场景里所有引用变成 `Missing`
- `Resources.Load` 按路径仍能取到（路径没变的话），于是**一半能用一半不能用**

所以移动脚本一律「`.png` 与 `.png.meta` 成对搬」，并且新建目录时必须写 folder meta（`folderAsset: yes`）。

### 5.3 导入设置按**文件名**匹配，不要按目录

各项目的 `AssetPostprocessor` 覆盖 `Resources/UI/` 下的导入设置（sprite 类型、9-slice 边距）。这些规则必须写成「按文件名/前缀判断」，而不是「按完整路径判断」—— 否则素材一分类，导入设置全部失效，症状是圆角被拉变形，只在拉伸时可见。

## 6. 字体（与贴图同级的共用资源）

字体不属于上面六个 sprite 分类，但适用同样的两条纪律：**唯一入口** 与 **硬引用必须可校验**。

| 约定 | 理由 |
|---|---|
| 放 `Assets/Resources/Font/`，文件名用 ASCII | `Resources.Load` 与构建管线对中文文件名不保证可靠 |
| 运行时只有一个取字体的入口（S：`UiKit.Font`） | 换字体时改多处，漏一处就有一批文字仍是旧字体，肉眼极难发现 |
| 编辑器序列化预制体要用 `AssetDatabase.LoadAssetAtPath` | `Resources.Load` 取的是运行时实例，写不进预制体 |
| 缺字体时静默回退内置字体 + `LogWarning` | 退化成"字体不对"而不是"文字全没" |
| 预制体里的 `m_Font` 全部硬 GUID 引用同一个字体 | Unity 对缺失字体会**静默**显示 Missing (Font)，不报错 |

字体缺失是隐性故障：界面照常打开，只是字全没了或全变成默认字体，**打包、单测、自检都可能全部通过**。所以必须两道断言：

1. 编辑器侧：资产存在 + `Resources` 路径可取 + GUID 与实际引用一致 + 预制体引用数对得上
2. 运行时：取到的字体名不是内置回退字体

## 7. 校验（必须接进自动化）

每个项目都要有一个分类一致性校验，作为 `check.ps1` 的固定步骤。判据七条：

| # | 判据 | 失败意味着 |
|---|------|-----------|
| 1 | `Resources/UI/` 根目录无 `.png` | 有素材没分类 |
| 2 | 代码里的分类表 ↔ 磁盘文件 一一对应 | 登记了没有 / 有却没登记 |
| 3 | 每个素材都在它登记的目录里 | 移动了但没更新表 |
| 4 | `Icon/Items` 全是 `item_*` | 数据驱动目录被塞了静态图标 |
| 5 | 各工具链的分类表与代码一致 | 两份拷贝漂移 |
| 6 | 配件图标 ↔ 数据 id 完全相等 | 缺图或废弃残留 |
| 7 | 磁盘文件名无重复 | 分类时漏了同名的第二份 |

判据 2 与 6 的失败是**静默**的：缺图时界面按设计降级成纯色块，不报错。所以不能靠看图发现，必须有脚本。

参考实现：`<GAME:S>/tools/audit_ui_taxonomy.py`（退出码 0/1，已接入 `check.ps1 -Task tests`）。

字体另有两条独立判据（见 §6）：编辑器侧资产/GUID/引用一致性，运行时非内置回退。
参考实现：`<GAME:S>/Assets/_Game/Editor/SUiFontSetup.cs` + `SelfCheck` 的字体断言，
已接入 `check.ps1 -Task ui` 的第 5 步。

## 8. 新增一张素材的完整流程

1. 按 §3 判定分类
2. 原图放 `<GAME>/_Inbox/ui-ai-raw/`（原料入库，换机不用重生成）
3. 在流水线的分类表里登记（一行）
4. 跑流水线，产物落到 `Assets/Resources/UI/Sprites/<Category>/`
5. 在运行时分类表里登记（S：`UiAssets.Catalog`）
6. 跑校验脚本，七条全绿
7. 若该素材参与 9-slice，同步 `AssetPostprocessor` 的边距表与校验脚本的期望值

**第 3 步和第 5 步是最容易漏的两步** —— 而且漏了不会报错。所以 §6 的校验是必需项，不是可选项。

## 9. 与其它规则的关系
